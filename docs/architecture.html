Architecture

Isolated modules, Pcap2HDL-style. Changing the trace path does not rebuild. Changing HDL or DPI sources does.

Trace (.log / .csv) │ ▼ dpi/tlp_reader.c open · parse · pack 4 beats · C tallies (+ TYPE/DIR/BDF filter · drop Cpl in DUT mode) │ ▼ DPI-C tb_tlp_dpi.sv AXIS driver tdata/tvalid/tready/tstart/tlast │ ├──► tlp_header_parser.sv hdr_* on last beat ├──► tlp_cfg_dut.sv cfg image · Cpl on PAIR (optional) │ │ │ └──► AXIS Cpl beats (muxed back onto bus) └──► tlp_match_tracker.sv complete / open / matched │ ▼ Scoreboard HDL counters ≟ get_c_*() / DUT cpl_tx → mis=0 │ ▼ simulation_trace.vcd

Endpoint DUT

Not a NIC or PHY — a config-space slave for one completer BDF.

Host TLPDUT action
CfgRd · pair (empty payload)Emit teaching-AXIS Cpl with cfg DWORD
CfgRd · complete (payload)Seed cfg image (seed++); no Cpl
CfgWrUpdate Command / BARs (incl. 0xffffffff size probe)
With +DUT_BDF=, DPI drops capture Cpls and keeps only requests to that completer. Match closes on DUT completions. Prefer a BDF with TX empty CfgRd (e.g. 0100 = 00:01.0) to exercise cpl_tx.

Match semantics

Aligned with pcieshark:

Hint / eventMeaning
match_hint = 1Request with payload → complete
match_hint = 2Request without payload → pair (open slot)
CplCloses by tag → matched; else unmatched
DUT CplSame Cpl path; closes PAIR opened by host CfgRd

What this is not

Not a PCIe PHY, PIPE, or commercial VIP. The AXIS-TLP bus and cfg DUT are teaching and bring-up abstractions so TLPs can be observed like AXIS bytes in L2AxisBr and gated like packets in Pcap2HDL. 
make dut
# [DUT] bdf=0300 hit_rd=6 hit_wr=4 cpl_tx=6 seed=0
# [GATE] mis=0  PASS
